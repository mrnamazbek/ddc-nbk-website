# Figma MCP Research Report

## 1. What is Figma MCP — Summary

Model Context Protocol (MCP) для Figma представляет собой открытый стандарт интеграции, который позволяет ИИ-ассистентам и средам разработки напрямую взаимодействовать с API Figma. Вместо того чтобы анализировать дизайн по статичным скриншотам или растровым изображениям, ИИ-агент получает доступ к структурированным векторным и объектным данным макета в реальном времени. Это решает проблему неточного переноса интерфейса в код, исключая ошибки в размерах, цветах, отступах и иерархии компонентов. Figma MCP кардинально отличается от классического Figma Dev Mode тем, что ориентирован на машинное чтение данных (M2M), а не на человеческий визуальный осмотр. Данная технология была официально представлена и стала общедоступной в начале 2025 года, открыв новую эру автоматизированного проектирования интерфейсов.

## 2. How it works — Technical Architecture

Техническая архитектура взаимодействия строится на базе протокола JSON-RPC и состоит из трех ключевых звеньев:

```
┌─────────────┐           ┌────────────────┐           ┌──────────────────┐
│  Figma API  │  ◄──────  │   Figma MCP    │  ◄──────  │  IDE / AI Agent  │
│  (Cloud)    │  (HTTPS)  │  Server (HTTP) │ (JSON-RPC)│ (Cursor/Claude)  │
└─────────────┘           └────────────────┘           └──────────────────┘
```

### Схема потока данных
1. **Запрос ИИ-агента:** Разработчик передает ИИ-агенту ссылку на конкретный фрейм или компонент Figma.
2. **Запрос к MCP серверу:** ИИ-агент обращается к подключенному MCP-серверу (локальному или удаленному) по протоколу JSON-RPC.
3. **Получение данных из Figma API:** MCP-сервер запрашивает метаданные из облака Figma через REST API, используя токен авторизации (OAuth или Personal Access Token).
4. **Передача структурированного контекста:** MCP-сервер преобразует сырой JSON-ответ Figma в структурированное дерево свойств и передает его ИИ-агенту.

### Данные, передаваемые ИИ-агенту
* **Иерархия слоев (Layer Tree):** Типы узлов (FRAME, TEXT, INSTANCE), порядок вложенности.
* **Параметры Auto-Layout:** Направление (flex-direction), отступы (padding, gap), выравнивание и правила растяжения (hug, fill, fixed).
* **Свойства стилей:** Цветовые заливки (solid, gradients), тени (drop-shadow), размытия (backdrop-filter) и параметры скругления углов.
* **Переменные и токены (Figma Variables):** Семантические переменные цвета, размеров и шрифтов.
* **Свойства текста:** Семейство шрифтов, размер (fontSize), высота строки (lineHeight), начертание (fontWeight).
* **Метаданные компонентов:** Названия вариантов, текущие состояния и ссылки на Code Connect для связи с реальными файлами React/HTML.

## 3. Current tool support

| IDE / Инструмент | Уровень поддержки | Особенности интеграции |
| :--- | :--- | :--- |
| **Cursor** | Высокий | Поддержка кастомных HTTP-серверов в разделе Tools -> MCP. ИИ-ассистент считывает ссылки на Figma-файлы и генерирует точный CSS/TSX код. |
| **VS Code (Copilot)** | Высокий | Нативная интеграция через Copilot Chat и конфигурационный файл `mcp.json`. Поддерживает как удаленный, так и локальный запуск. |
| **Claude Code (CLI)** | Высокий | Полноценная поддержка через встроенный плагин figma или команду `/mcp`. ИИ имеет прямой доступ к чтению дерева макетов. |
| **Antigravity IDE** | Выдающийся | Интегрированная поддержка на уровне системных плагинов и конфигурации `mcp_config.json`. Позволяет ИИ работать как с токенами, так и с 3D-ассетами. |
| **Windsurf** | Средний | Поддержка через интеграцию внешних MCP-серверов. Требует ручной прописки путей к исполняемым файлам Node.js. |

## 4. Professional Figma workflow for website design

Создание премиального корпоративного веб-сайта (такого как DDC / NBK) требует строгого системного подхода. Пошаговая структура проектирования в Figma выглядит следующим образом:

### Шаг 1: Определение дизайн-токенов (Global Variables)
До создания первых экранов дизайнер определяет базовые константы бренда в панели Variables:
- **Цветовая палитра (Primitives):** Синий (`#005cbb`), золото (`#C9A84C`), угольный (`#08080a`), белый (`#ffffff`).
- **Семантические цвета:** фоны (`bg-primary`, `bg-glass`), границы (`border-gold`, `border-blue`), акценты.
- **Сетка отступов (Spacing Scale):** Базовый шаг 4px (4, 8, 12, 16, 24, 32, 48, 64).
- **Скругления (Radius Scale):** `radius-sm` (4px), `radius-md` (8px), `radius-lg` (16px), `radius-xl` (22px).

### Шаг 2: Создание компонентной библиотеки (Atomic Design)
Интерфейс собирается из переиспользуемых атомарных элементов:
- **Кнопки:** Варианты для разных типов (gold, blue, outline) и состояний (default, hover, active, disabled).
- **Карты (GlassCard):** Контейнеры с настроенным эффектом матового стекла и градиентными рамками.
- **Навигационные элементы:** Ссылки меню, элементы хедера и футера.

### Шаг 3: Проектирование с использованием Auto-Layout
Все фреймы должны использовать Auto-Layout. Использование абсолютного позиционирования (Absolute Positioning) допускается только для сложных декоративных 3D-свечений или интерактивных курсоров. Auto-Layout гарантирует, что ИИ-агент сможет сгенерировать адаптивную разметку (Flexbox / Grid) без «захардкоженных» координат.

### Шаг 4: Структурирование страниц файла
Для больших проектов файл Figma структурируется по страницам:
- `README / Cover` — обложка и описание проекта.
- `📐 Design Tokens` — глобальные переменные, стили и шрифты.
- `❖ Components` — библиотека Master Components.
- `🖥️ Desktop Templates` — финальные макеты экранов для десктопа (1440px).
- `📱 Mobile Templates` — адаптивные макеты экранов для мобильных устройств (375px).

## 5. Design patterns found

Для веб-сайтов государственных и финансовых институтов характерны следующие паттерны проектирования:

### 5.1. Паттерны разметки (Layout Patterns)
- **Bento Grid:** Мозаичная структура для представления статистики, преимуществ или технологических модулей. Позволяет компактно разместить разнородную информацию (графики, списки, часы).
- **Hero-секция с ассиметричным балансом:** Строгий текстовый блок слева (высокая типографика, золотые акценты) и интерактивный WebGL/3D-объект справа.
- **Информационные таймлайны:** Линейные или зигзагообразные структуры для демонстрации этапов развития, дорожных карт или ключевых принципов работы.

### 5.2. Компонентные паттерны (Component Patterns)
- **Премиальный матовый глассморфизм (Glassmorphic Containers):** Использование полупрозрачных фонов со сверхвысоким размытием (`backdrop-filter: blur(20px)`) и тонкими светлыми границами.
- **Spotlight Border (Световая граница):** Эффект подсветки границ карты вслед за курсором мыши, подчеркивающий премиальность интерфейса.
- **Живые часы и виджеты данных (Live Widgets):** Встраивание интерактивных элементов реального времени ( Astana Time, журнал транзакций Цифрового Тенге).

### 5.3. Паттерны передачи в код (Handoff Patterns)
- **W3C Design Tokens JSON:** Экспорт переменных в формате, совместимом со Style Dictionary.
- **Component Association (Code Connect):** Привязка ссылок на компоненты в кодовой базе напрямую к фреймам Figma, чтобы ИИ знал о существовании готовой кнопки и не генерировал новую.

## 6. AI + Figma MCP workflow

### Пример сквозного процесса разработки:
1. **Подготовка макета:** Дизайнер создает фрейм карточки транзакции с автолейаутом, скруглением 16px, фоном `rgba(10, 10, 12, 0.45)` и шрифтом `Inter`.
2. **Получение ссылки:** Разработчик копирует ссылку на этот фрейм в Figma.
3. **Запрос к ИИ:** Разработчик отправляет запрос в Cursor/Antigravity IDE:
   > «Сгенерируй компонент TransactionCard на базе макета [Ссылка на Figma] с использованием Tailwind CSS».
4. **Анализ через MCP:** ИИ-агент обращается по ссылке через Figma MCP, считывает JSON-структуру макета и видит:
   - Направление Auto-Layout: по вертикали (flex-direction: column).
   - Внутренние отступы: 24px (p-6).
   - Скругление углов: 16px (rounded-lg).
   - Цвет фона и параметры размытия: `backdrop-filter: blur(16px)`.
5. **Генерация точного кода:** ИИ-агент создает React-компонент, в котором стили в точности соответствуют токенам Figma, избегая неточных визуальных приближений.

## 7. Limitations and workarounds

| Ограничение Figma MCP | Технические последствия | Временное решение (Workaround) |
| :--- | :--- | :--- |
| **Отсутствие визуального контекста** | ИИ получает только JSON-дерево свойств, но не видит сложную растровую графику или 3D-текстуры. | Использовать мультимодальный ввод: передавать ИИ-агенту ссылку на Figma MCP вместе со скриншотом макета для оценки визуала. |
| **Ограничения контекстного окна** | Чтение гигантских файлов с тысячами слоев может переполнить контекстное окно модели ИИ. | Передавать ссылки на конкретные изолированные фреймы или компоненты, а не на весь дизайн-файл. |
| **Сложные градиенты и шумы** | Сложные многослойные эффекты (например, Apple Liquid Glass с процедурным шумом) трудно транслируются в плоский CSS. | Описывать сложные стили вручную в файле `globals.css` в виде базовых утилит, а в Figma ссылаться на них через имена переменных. |
| **Интерактивные анимации** | Figma MCP не может экспортировать сложные триггеры анимации в код для Anime.js или Framer Motion. | Анимационную логику (stagger-эффекты, кинетическое сглаживание) прописывать вручную, опираясь на дизайн-гайдлайны. |

## 8. Recommended tools alongside Figma MCP

Для создания автоматизированного дизайн-конвейера рекомендуется использовать:
- **Tokens Studio for Figma (plugin):** Лучший инструмент для создания и ведения многоуровневых дизайн-токенов (глобальных, семантических, компонентных) и синхронизации их с GitHub.
- **Style Dictionary:** Мощный фреймворк для сборки дизайн-токенов. Преобразует JSON-файлы из Tokens Studio в CSS-переменные, переменные Sass или Tailwind CSS.
- **Figma Code Connect:** Официальная утилита от Figma для сопоставления дизайна и кода, исключающая дублирование компонентов при совместной разработке с ИИ.

## 9. Setup status

**СТАТУС КОНФИГУРАЦИИ:** `CONFIGURED ✅`

Конфигурационный файл среды разработки успешно настроен для интеграции с официальным Remote MCP сервером Figma.

### Актуальная конфигурация (`mcp_config.json`):
```json
{
  "mcpServers": {
    "figma": {
      "url": "https://mcp.figma.com/mcp"
    }
  }
}
```

### Предварительные требования для пользователя:
1. **Персональный токен доступа (PAT):** Предоставлен и сохранен локально (`figd_YOUR_FIGMA_PAT_HERE`). Он будет использоваться кастомными плагинами и локальными скриптами экспорта токенов.
2. **Авторизация сессии:** При первом обращении ИИ-агента к ссылке Figma в чате IDE может потребоваться однократное подтверждение OAuth-авторизации в открывшемся окне браузера.

## 10. Recommended next steps for our NBK/DDC project

Для нашего проекта разработки премиального сайта ЦЦР и Национального Банка РК мы рекомендуем следующий пайплайн:

### 10.1. Стратегия разработки: Сначала код, затем синхронизация с Figma
Учитывая, что у нас уже разработана и верифицирована сложная техническая архитектура (WebGL 3D-сцена на Three.js, кинетические счетчики на Anime.js v4, ультимативный стеклянный стиль Apple Liquid Glass в `globals.css`), мы рекомендуем стратегию **Code-First с последующим импортом дизайн-токенов**:
1. Мы используем наш существующий `globals.css` как фундамент дизайн-системы.
2. В Figma создается пустой проект с соответствующими переменными цвета (`--color-brand-blue`, `--color-gold`, `--glass-bg`), которые в точности соответствуют CSS-переменным нашего сайта.
3. Это позволит дизайнеру работать в едином семантическом поле с разработчиком с первого дня.

### 10.2. Создание структуры файла Figma для DDC / NBK
Мы рекомендуем следующую структуру страниц в Figma-проекте:
1. `❖ Global Tokens` — палитра цветов ЦЦР и Нацбанка, шкала скруглений (radius-xl для премиального скругления карт), отступы.
2. `❖ Components / Glassmorphism` — мастер-компоненты стеклянных карт (GlassCard), кнопок со Spotlight Border и элементов навигации.
3. `🖥️ Desktop Screens` — дизайн основных разделов сайта (Hero, About, DigitalShowcase, Security, Careers, Contacts).
4. `📱 Mobile Screens` — адаптивные мобильные интерфейсы.

### 10.3. Первое действие в Figma
Загрузите ваш дизайн-файл или создайте новый, скопируйте ссылку на главный контейнер страницы и пришлите ее в наш чат. Используя настроенный Figma MCP и ваш персональный PAT, мы сможем мгновенно прочитать переменные и внедрить их в нашу кодовую базу.
